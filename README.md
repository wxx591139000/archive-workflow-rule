# 归档整理工作流

> 对齐 GPT 5.6 归档动作的标准项目归档流程 — 在 Claude Code 中一句「归档整理」自动执行

> **版本：v2.0**（2026-08-19 · 新增「交接准备」机制，服务 `/clear` 无缝续接）

## 📋 概述

本项目定义了一套标准化的项目归档整理流程，适用于 Claude Code 环境。在任何项目目录下说出 **「归档整理」**，AI 助手将自动执行完整归档流程：生成 5 份核心项目文档、完成 Git 归档，并在末尾产出**交接准备**——让你归档后可以放心 `/clear`，下次说 **「按交接提示继续」** 即可无缝衔接任务继续推进。

## ✨ 核心功能

| 功能 | 说明 |
|------|------|
| 🏷️ Git 归档 | 自动提交、推送、打 Tag |
| 📄 项目目标 SPEC | 生成 `/docs/SPEC.md` — 定位、功能、技术栈 |
| 🏗️ 项目详细方案 | 生成 `/docs/ARCHITECTURE.md` — 架构、模块、数据流 |
| 🧪 项目测试计划 | 生成 `/docs/TEST_PLAN.md` — 测试策略、覆盖情况 |
| ⚠️ 项目踩坑记录 | 生成 `/docs/PITFALLS.md` — 从代码注释提取的坑 |
| 📊 项目推进进度 | 生成 `/docs/PROGRESS.md` — 里程碑、待办事项 |
| 🧹 自动清理 | 删除构建产物和临时文件 |
| 📝 归档摘要 | 生成 `/docs/archive-<YYYYMMDD>.md` 归档报告 |
| 🔗 交接准备 | 归档后自动产出 resume-handoff 记忆 + handover 快照 + MEMORY.md 索引 + 交接文档 |
| 🔄 `/clear` 续接 | 交接后放心 `/clear`，下次说「按交接提示继续」无缝衔接 |

## 🚀 使用方法

### 前提条件

- [Claude Code](https://claude.ai/code) 环境
- 项目已初始化 Git 仓库（可选，非 Git 项目跳过 Git 相关步骤）

### 一句话触发

在项目目录下，直接对 Claude Code 说：

```
归档整理
```

AI 助手将自动执行完整流程：

```
1. 代码分析 → 扫描项目结构、配置文件、Git 历史
2. Git 提交 + 推送 → 打 Tag archive-YYYYMMDD
3. 生成 5 份核心文档 → /docs/ 目录下
4. 更新 README + CHANGELOG
5. 清理构建产物
6. 生成归档摘要 → /docs/archive-YYYYMMDD.md
7. 交接准备 → 产出 resume-handoff 记忆 + handover 快照 + MEMORY.md 索引 + 交接文档（服务 /clear 续接）
8. 输出归档报告
```

### 高级用法

| 指令 | 效果 |
|------|------|
| `归档整理，不推 Git` | 跳过 Git 提交和推送 |
| `归档整理，只更新 SPEC 和进度` | 只更新指定文档 |
| `归档整理` | 全自动执行完整流程 |

### 在 Claude Code 中固化规则

如果想在自己本地的 Claude Code 中使用这套流程，只需：

1. 告诉 Claude Code：「保存归档整理规则」
2. 将本仓库的 [`归档整理工作流说明.md`](归档整理工作流说明.md) 内容提供给它
3. Claude Code 会自动固化规则，之后在任何项目目录说「归档整理」即可触发

| 文件 | 说明 |
|------|------|
| `归档整理工作流说明.md` | 归档整理规则的完整说明文档 |
| `README.md` | 本文件 — 使用说明 |

## 📝 生成文档结构

归档执行后，目标项目将生成以下文档：

```
项目根目录/
├── docs/
│   ├── SPEC.md              # 项目目标 SPEC
│   ├── ARCHITECTURE.md       # 项目详细方案
│   ├── TEST_PLAN.md          # 项目测试计划
│   ├── PITFALLS.md           # 项目踩坑记录
│   ├── PROGRESS.md           # 项目推进进度
│   └── archive-YYYYMMDD.md   # 归档摘要
├── README.md
├── CHANGELOG.md
└── ...
```

## ⚙️ 流程详情

### 步骤 1：代码分析
扫描项目文件结构、主要代码文件、配置文件，分析 README、package.json、pyproject.toml 等元数据，提取 Git 提交历史，识别技术栈和主要模块。

### 步骤 2：Git 归档
```bash
git add .
git commit -m "归档: <项目名> <YYYY-MM-DD>"
git push
git tag archive-<YYYYMMDD>
git push --tags
```

### 步骤 3：文档生成
基于代码分析结果，自动生成 5 份核心文档，每份文档基于实际代码内容，而非模板填充。

### 步骤 4：清理
删除 `build/`、`dist/`、`temp/`、`__pycache__/`、`.cache/`、`*.log` 等构建产物。

### 步骤 5：交接准备（服务 /clear 无缝续接）
归档后自动产出交接物，保证 `/clear` 后仍能无缝续接：
1. 收集交接数据（项目名/路径/Git+tag/版本/公网/启动方式/待办/硬约束）
2. 写「续接提示」记忆 `<项目>-resume-handoff.md`（说「按交接提示继续」即读它对标，已存在则增量更新）
3. 写「单次交接」记忆快照 `<项目>-handover-YYYY-MM-DD.md`
4. 为两者在 `MEMORY.md` 补索引行（**新会话只自动加载 MEMORY.md，交接记忆必须被索引才续接不丢锚点**）
5. 写交接文档（每项目独立放项目内 `docs/接交接.md`，多项目时共享文件只作指针）

> **多项目隔离**：交接记忆/文档按项目 slug 命名，各自独立、互不覆盖。

### 步骤 6：归档报告
输出归档标签名、5 份文档路径、交接产物、文件变更统计、清理结果。

## 🔄 服务 /clear 无缝续接

```text
说「做个归档」→ skill 归档 + 自动交接准备（写记忆 + 索引 + 交接文档）
       ↓
      /clear（可放心清）
       ↓
新会话自动加载 MEMORY.md → 看到该项目的交接记忆
       ↓
说「按交接提示继续」 → 读 resume-handoff + handover 记忆，对齐锚点，无缝开干
```

## 🔒 约束

- 如果项目没有 `/docs/` 目录，自动创建
- 如果当前目录不是 Git 仓库，跳过 Git 相关步骤，仅做文档生成与更新
- 已有文档不做全量覆盖，基于分析增量更新（保留用户手动添加的内容）
- 文档生成使用中文
